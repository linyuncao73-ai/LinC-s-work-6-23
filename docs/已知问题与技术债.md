## 已知 Bug

### P0

**（暂无已知的会导致排班错误的 P0 bug。）** 当前主流程（导入 → Auto-Assign → 拆线 → 报告 → 回填 → 同步）稳定运行中。

### P1

- **中介反馈的两级拆分后缀 `b.1.1` / 深层后缀解析不全**
  `services/feedbackParser.ts` 的 `splitSegSuffix()` 只剥一层 `.n` 后缀。当中介把一刀线再分给第二个司机、写成 `330xx-a-b.1.1` 时，会被当成基线 `b.1` 处理、匹配不到 → **该行被静默丢弃**。
  影响：这种深层拆分的反馈需要手动在 Editor 里改。
  修法方向：`splitSegSuffix` 改为剥全部数字后缀返回路径数组（如 `[1,1]`），`FeedbackSegment.partIdx` 改为字符串路径键（`"1.1"`），`applyFeedbackOps` 的部件表按路径键匹配。（这个方案之前设计过，未实施。）

- **反馈里解析不出的行不提示**
  `parseFeedbackTextLocal` 对认不出的行直接跳过，预览界面不显示"哪几行没被识别"。用户可能以为全套用了，其实漏了。
  修法方向：解析返回值加 `skipped: string[]`，FeedbackModal 预览区用黄条列出未识别的原始行。

### P2

- **flaky 测试（已修）**：加密 round-trip 曾因 base64 密文里随机出现裸 `r1` 而偶发失败，已改为带引号断言。留记录以防回潮。

## 技术债（按优先级）

### P1

- **`App.tsx` 单文件约 2700 行**
  所有组件、所有状态、所有 handler 挤在一个文件。这是最大的结构性债。好处是定位集中；坏处是难以测试（UI 无自动化测试）、改一处怕碰另一处、新人上手慢。
  拆分建议：先把独立组件（各 Modal、各 View）拆到 `components/`，再把 handler 逻辑抽成可测的纯函数放 `services/`。**拆的时候一次只搬一个组件、跑一遍手动验证**，别一次大重构。

- **Supabase 匿名 RLS 完全开放 + 加密可选**
  匿名 key 公开、RLS 对 anon 全开（可读可写）。唯一保护是团队口令加密——但加密是**可选的**，没设口令时数据以明文存在云端，任何拿到 URL 的人都能读写。
  风险：URL 泄露 + 没设口令 = 排班数据（含司机号）公开可见/可篡改。
  缓解建议：强制要求设团队口令；或加一个"读写需带一个共享 secret 头"的轻校验（需要 Supabase Edge Function 或 RLS policy 配合，会增加架构复杂度）。当前团队内部用、风险可接受，但接手者应知晓。

### P2

- **Tailwind 用 CDN（`index.html` 的 `cdn.tailwindcss.com`）**
  开发方便，但：①CDN 挂了页面就没样式；②生产环境用 CDN 版 Tailwind 官方不推荐（有性能/体积警告）；③无法 tree-shake。
  处理建议：迁到 Vite 的 PostCSS + Tailwind 构建集成，样式打进 bundle。

- **无 Error Boundary**
  某个组件抛错会白屏。加一个顶层 React Error Boundary 显示友好提示 + 重载按钮。

- **`xlsx` 依赖体积大**（构建里 ~429KB 的 chunk）
  已经是懒加载。若 Excel 上传路径使用率低（现在推荐粘贴导入），可考虑进一步按需加载或替换更轻的库。

- **localStorage 与云端可能漂移**
  本地是事实源，云同步靠合并 + 墓碑 + `edited` 标记，逻辑较绕（见隐藏逻辑文档第 9 节）。"改了没生效"类问题多源于此。长期看，收敛成"云端优先 + 明确的冲突解决"会更健壮。

- **元信息过时**
  - `README.md` 还是 AI Studio 模板内容，与真实项目无关，应重写或删。
  - `package.json` 的 `name` 是 `"yow-dispatch-assistant-use-this-one-update-feb-02/02"`（含斜杠，不规范），可改成正常名字。
  - 部署 workflow 里挂着一个很长的功能分支名 `claude/scheduling-system-improvements-pf3cni` 作为部署分支。交接后建议把成果合并进 `main`，只用 `main` 部署，删掉这个分支触发器。

## 给接手者的排雷清单

1. 改路线/司机默认值 → 一定先读 `隐藏逻辑与业务规则.md` 的 `PLACEHOLDER_MAPPING` 和名册优先级。
2. 改 `services/`、`types.ts` → 先 `npm test`。
3. 部署无预发、push 即上线 → 重要改动先本地 `npm run build`。
4. 永远别把 Gemini key 写进任何文件。
5. 想清理代码，先从删 E-binder 死代码、重写 README 这类低风险项开始，别一上来就拆 `App.tsx`。
